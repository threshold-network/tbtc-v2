= Threshold cross-chain - Solana

== NTT migration

The existing Solana deployment uses a Wormhole Token Bridge lockbox gateway. The
custom tBTC program owns the SPL mint through its `config` PDA, and the gateway
custodian mints canonical tBTC against wrapped Wormhole tBTC held in custody.

Before Solana can be configured as an L1 NTT peer:

1. Pause the existing tBTC program and Wormhole gateway.
2. Burn or otherwise migrate all canonical Solana tBTC so the SPL mint supply is
   zero.
3. Remove all configured legacy tBTC minters.
4. Drain or otherwise reconcile the gateway custodian's wrapped-token lockbox.
5. Deploy and initialize the Wormhole NTT manager/transceiver in burning mode.
6. Transfer the SPL mint authority from the tBTC `config` PDA to the NTT token
   authority PDA, or to an SPL multisig that contains the NTT token authority PDA.

The tBTC program exposes `transfer_mint_authority` for the last step. It requires
the program to be paused, the SPL mint supply to be zero, all minters to be
removed, a non-default new authority, and signatures from both the tBTC authority
and an active guardian. The guardian must be a separate key from the authority
and should be held by an independent operator before the cutover; the program
enforces key separation, but operational independence is a governance
requirement. Because guardian registration is authority-controlled, the guardian
co-signature should be treated as true two-party control only when the guardian
was pre-established under independent custody.

`transfer_mint_authority` additionally requires at least two guardians to be
registered at call time. A lone registered guardian only proves the co-signer
holds a distinct pubkey from the authority, which a compromised or malicious
authority can satisfy trivially by registering one puppet key it also
controls and immediately co-signing with it. Requiring a second registered
guardian raises the operational bar without changing the on-chain
authorization model, and gives program-level parity with the equivalent
`retire_gateway_for_ntt` dual-signer requirement on the Sui tBTC gateway.

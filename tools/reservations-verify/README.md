# Reservation re-verification bundle

Runs the targeted checks on one tbtc-v2 head and prints one pass/fail table.
Use it each time the public PR head moves or the integrated line changes.

```text
tools/reservations-verify/run.sh \
  --tbtc /path/to/tbtc-v2-worktree \
  [--keepcore /path/to/keep-core-worktree] \
  [--fork-ref <git ref that holds solidity/scripts/reservations-fork-*.ts>] \
  [--old-head <PR head before it moved> --new-head <PR head now> [--reference <ref>]] \
[--steps reconcile,killset,full,survivors,exclusions,sdk,fork,drift]
```

| Step         | What it runs                                                                                                                                                                                                                                                                                                                                                                                      | Typical cost |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------ |
| `reconcile`  | normalizes `solidity/contracts` and `solidity/deploy` with the repository Prettier at the old and new PR head and at the head under test, then checks that every real change of the PR is already in the head under test (`reconcile.sh`); with `--reference` it also compares the contracts at that ref with the head under test. Exits 1 for a missing contract change or a contract difference | about 2 min  |
| `killset`    | compile, then the 262 reservation tests in `killset.txt` plus the survivor tests                                                                                                                                                                                                                                                                                                                  | about 2 min  |
| `full`       | the full Hardhat suite                                                                                                                                                                                                                                                                                                                                                                            | about 6 min  |
| `survivors`  | re-applies the nine mutants in `survivors.txt` (one source string each, see `mutate.cjs`), runs the three test files that must kill them, restores the source and checks its hash                                                                                                                                                                                                                 | about 10 min |
| `exclusions` | checks that every uncovered coverage unit and every surviving mutant has a written reason in `exclusions.txt` (`check-exclusions.js`); exits 1 when one has none                                                                                                                                                                                                                                  | seconds      |
| `sdk`        | generates typechain bindings, runs the SDK suite                                                                                                                                                                                                                                                                                                                                                  | about 1 min  |
| `fork`       | mainnet-fork lifecycle, SDK and hand-off scripts (needs `FORKING_URL` in the environment and `--fork-ref`)                                                                                                                                                                                                                                                                                        | about 2 min  |
| `drift`      | keep-core `verify-vendored-fallback` against artifacts compiled from this head (needs `--keepcore`)                                                                                                                                                                                                                                                                                               | seconds      |

Without `--steps` it runs every step the arguments allow.

## Notes

- The tbtc-v2 worktree needs `solidity/node_modules` and `typescript/node_modules`. Run one Hardhat job at a time: memory is the limit.
- `mutate.cjs` replaces exact source strings. If the contract text changes (for example after a Prettier pass), a mutant reports `PATTERN_NOT_FOUND` instead of `KILLED`; fix the string, do not count it. `RES_INDENT` selects the indent of the `isPrivileged` continuation lines (16 after Prettier).
- The fork step writes four fork scripts from `--fork-ref` into `solidity/scripts/`, runs them, and removes them and the artifacts it wrote.
- Pass floors: a step passes only with no failures and a minimum number of passing tests (`MIN_KILLSET` 200, `MIN_FULL` 3000, `MIN_SDK` 500, `MIN_FORK` 20 fork passes). "0 passing, 0 failing" is a FAIL.
- `survivors` first runs the unmutated kill set and stops (row FAIL, no mutant run) unless it is green with at least one passing test. A mutant is `KILLED` only when at least one test still passed and at least one test failed on an assertion; a failure count without a failing test name is `UNCONFIRMED`. A run that dies in a setup hook (`"before all"`/`"after each"` and the like), a run where no test passed at all, and a run that did not compile are `NOT_VIABLE`: the mutant never met an assertion, so the verdict says nothing about it, and the step reports those apart from the mutants the tests caught. The step passes only when every id in `survivors.txt` ran and was `KILLED`. `node tools/reservations-verify/mutate.cjs <worktree> --self-test` plants a broken `before()` hook and an assertion failure to prove the two verdicts.
- Full suite on the integrated head (run twice, once before and once after the four getter tests): the first run had one failure, `L1BTCDepositorNttWithExecutor - Real-World Scenarios / should handle different fee structures`; the second run had none (3568 passing, 61 pending). On the PR head at the time of that measurement it had 3488 passing, 61 pending, 0 failing. The failing test passes alone. Treat a repeat as a new finding.
- No log contains URLs or keys: the fork log passes through a URL filter.
- Not covered: Medusa and Foundry invariants, Go fuzz and mutation, the keep-core test suite. The `reconcile` step with `--reference` shows whether the contract bytes differ from the reference revision after formatting; run those suites when it reports a difference.
- The drift step recompiles first (the survivors step leaves artifacts of the last mutant behind) and runs `make` with `GOTOOLCHAIN=go1.25.7` unless `GOTOOLCHAIN` is already set; keep-core's `go.mod` needs Go 1.25.7 or newer.
- `exclusions.txt` holds the units that a coverage or mutation report would otherwise report as a gap, each with the reason it is a gap and the decision that keeps it there. A row names a symbol, never a line range, because line numbers move with every contract change. `check-exclusions.js` reads the list against a `coverage-final.json` and a mutants JSON and fails when an uncovered unit or a surviving mutant has no row. Run it on its own with `node tools/reservations-verify/check-exclusions.js coverage --coverage <coverage-final.json>` or `node tools/reservations-verify/check-exclusions.js mutation --mutants <mutants.json>`; the `exclusions` step of `run.sh` runs both halves and takes the coverage report from `solidity/coverage/coverage-final.json` and the mutants from the `survivors` step, overriding either with `COVERAGE_REPORT` or `MUTANTS_JSON`. The coverage half is scoped to the files the exclusion list names, so it answers the question the list is about; `--scope <path prefix>` widens it to other files.
- `slither-triage.txt` holds one row per Slither finding inside the bar's own scope, `solidity/contracts/bridge/`, with the detector, the file, the symbol, a verdict and the reason. The verdict is `false-positive` when the detector's claim does not hold here, `accepted` when the claim holds and the finding is accepted without a change in this release, and `open` for a real issue that must be fixed or decided. The bar `tbtc-v2.slither.findings` counts the in-scope findings that carry no row or carry `open`, so a row with a written reason is how a finding leaves the count, and no detector is switched off to get there. A row names a symbol, not a line, for the same reason `exclusions.txt` does. Run it with `node tools/reservations-verify/check-slither-triage.js --slither <slither.json> [--scope contracts/bridge/] [--head <sha>]`: it prints the findings table, each distinct reason once with the rows that share it, and the bar value. It exits 1 when an in-scope finding has no row, when a row is `open`, or when a row outlived the finding it names.
